# Протокол проверки FoodExpress

Схема `levykin_food`. Проверка от 21 ноября 2026 года. Доступ проверен отдельным подключением `inspector`. На сервере пользователя PostgreSQL 17.2 запрос вернул `inspector | 10 | 5` — роль, количество ресторанов и количество месяцев отчёта.

## Восстановление и прогон

В отдельной базе PostgreSQL 17 подготовлена схема `exts` с расширением `uuid-ossp`. В неё восстановлен архив `foodexpress_levykin.backup` в формате Custom, затем применён `schema/grants.sql`. Под `inspector` выполнены следующие проверки.

| Тикет | Проверка | Результат |
| --- | --- | --- |
| FOOD-101 | Восстановление схемы и чтение сведений через `information_schema.tables` и `pg_catalog.pg_tables`. | Схема восстановилась и доступна для проверки. |
| FOOD-102 | Два вызова `insert_test_data(10)` подряд. | 20 клиентов, 100 заказов, 120 выплат. |
| FOOD-103 | Два вызова `erase_test_data()` подряд в тестовой транзакции. | Оба выполнились. После очистки таблица клиентов и финансовый отчёт пусты. Изменения откатились. |
| FOOD-104 | Вызов `add_product` с действительными ID ресторана и категории. | Блюдо добавилось. До первого отзыва рейтинг равен `NULL`. |
| FOOD-105 | Изменение рейтинга отзыва, затем удаление последнего отзыва на блюдо. | Рейтинг стал `2`, после удаления стал `NULL`. |
| FOOD-106 | Вызов `get_statistic()` после генерации. | 10 строк после первого вызова генератора, 20 после второго. У каждого ресторана с доставками определены популярное блюдо и клиент, общий оборот не меньше среднего чека. |
| FOOD-107 | Два вызова `courier_salary()`. Подготовлены случаи с 150, 151, 250, 251, 500 и 501 доставкой. | Границы ставок подтвердились, дубликаты выплат не появились, исторические коэффициенты выплат сохранились. Коэффициенты уволенных курьеров остались прежними. |
| FOOD-108 | Чтение `how_much_money`, затем проверка месяца без доставок в тестовой транзакции. | 5 строк на исходных данных. Месяц без доставок присутствует с нулевой комиссией, следующая строка использует эту комиссию как предыдущую. |
| FOOD-109 | Отдельный вход под `inspector` по паролю и запуск перечисленных процедур и отчётов. | Доступ подтвердился. |
| FOOD-110 | `pg_restore` в пустую подготовленную базу, выдача прав, генерация и вызов отчётов. | Восстановление без ошибок, проверка вернула `inspector | 10 | 5`. |

В рабочей базе также получены сообщения `PASS: order payment status updated, test changes rolled back` и `PASS: last item deletion rejected`. Эти проверки подтверждают пересчёт статуса оплаты при ошибке платежа и запрет удаления последней позиции заказа.

## Запрос для повторной проверки после восстановления

Под `inspector` сначала вызовите генератор в пустой восстановленной схеме, затем выполните запрос:

```sql
CALL levykin_food.insert_test_data(10);

SELECT
    current_user AS connected_as,
    (SELECT COUNT(*) FROM levykin_food.get_statistic()) AS restaurants,
    (SELECT COUNT(*) FROM levykin_food.how_much_money) AS report_months;
```

Ожидаемые значения — `inspector`, `10` и `5`.
