# Ограничения FoodExpress

Схема `levykin_food` содержит 12 таблиц. В таблицах сущностей первичные ключи имеют тип `uuid` со значением по умолчанию `exts.uuid_generate_v4()`. В связях и ежемесячных выплатах первичные ключи составные. В `"order"` имя заключено в кавычки, поскольку `ORDER` зарезервировано PostgreSQL. BR-11.1, BR-13.1, FOOD-101.

## Ключи и ограничения таблиц

| Таблица | Правило в SQL | Назначение |
| --- | --- | --- |
| `client` | `UNIQUE (login)`, `UNIQUE (phone_number)`. Логин, телефон и пароль обязательны. | Регистрация и идентификация клиента, BR-2.1–2.3. |
| `address` | Улица и номер дома обязательны. `apartment_office` допускает `NULL`. | Адрес можно записать без квартиры или офиса, BR-3.1–3.2. |
| `client_address` | `PRIMARY KEY (client_id, address_id)`; внешние ключи на `client` и `address`. | Клиент может иметь несколько адресов. Каждый адрес привязывается к одному клиенту один раз, BR-2.4–2.5, BR-3.4. |
| `restaurant` | `address_id NOT NULL UNIQUE`, внешний ключ на `address`. | У ресторана один обязательный адрес, который может принадлежать только одному ресторану, BR-3.3–3.4. |
| `restaurant` | `CHECK (rating BETWEEN 0 AND 5)`, `CHECK (work_end > work_start)`. | Рейтинг и время работы, BR-4.1–4.5. |
| `product_category` | Название категории обязательно. | Справочник категорий, BR-5.7. |
| `product` | Обязательные внешние ключи `product_category_id` и `restaurant_id`. | Каждое блюдо относится к одной категории и одному ресторану, BR-5.1. |
| `product` | `CHECK (price >= 0)`, `CHECK (rating BETWEEN 0 AND 5)`. Колонка `photo_url` допускает `NULL`. | Цена, рейтинг и необязательная фотография, BR-5.2–5.6. |
| `courier` | `CHECK (coefficient BETWEEN 0.1 AND 0.5)`, значение по умолчанию `0.1`. | Границы и начальное значение коэффициента, BR-6.4–6.5. |
| `courier` | `CHECK ((status = 'уволен') = (dismissal_date IS NOT NULL))`, `CHECK (dismissal_date IS NULL OR dismissal_date >= hire_date)`. Дата найма обязательна. | Согласованность статуса и дат, BR-6.1, BR-6.3, BR-11.3. |
| `courier_pay` | `PRIMARY KEY (year, month, courier_id)`, внешний ключ на `courier`. | Одна выплата на курьера за месяц, BR-10.3. |
| `courier_pay` | `CHECK (month BETWEEN 1 AND 12)`, `CHECK (amount >= 0)`, `CHECK (coefficient_used BETWEEN 0.1 AND 0.5)`. | Допустимый месяц, неотрицательная выплата и фактически применённый коэффициент, BR-10.2–10.4. |
| `"order"` | Обязательные внешние ключи на `courier`, `client`, `address` и `restaurant`. Внешний ключ `(client_id, address_id)` на `client_address`. | Заказ связан с клиентом, рестораном и курьером. Адрес доставки принадлежит клиенту, BR-7.1–7.5. |
| `"order"` | `CHECK (total_amount >= 1000)`, `CHECK (commission = order_amount * 0.10)`, `CHECK (total_amount = order_amount + commission)`. | Фиксированная комиссия и минимальная сумма заказа, BR-1.4, BR-1.8, BR-7.10–7.11. |
| `"order"` | `CHECK (delivery_timestamp >= order_timestamp)`, `CHECK (status <> 'доставлен' OR delivery_timestamp IS NOT NULL)`. | Доставка происходит после оформления или в то же время. Доставленный заказ имеет время доставки, BR-7.12–7.13. |
| `"order"` | `UNIQUE (order_id, total_amount)`. | Даёт целевой ключ для проверки суммы платежа составным внешним ключом, BR-8.4. |
| `order_structure` | `PRIMARY KEY (order_id, product_id)`, внешние ключи на заказ и блюдо, `CHECK (quantity > 0)`. | Одно блюдо представлено одной позицией. Количество положительное и может быть дробным, BR-7.14–7.16. |
| `payment` | Внешний ключ `order_id` на заказ, внешний ключ `(order_id, amount)` на `"order"(order_id, total_amount)`, `UNIQUE (transaction_id)`. | Каждая попытка относится к одному заказу, имеет уникальный внешний ID и совпадает по сумме с заказом, BR-8.2–8.4. |
| `payment` | Частичный уникальный индекс на `order_id` для `status = 'успех'`. | Допускает несколько попыток и максимум одну успешную, BR-8.1 и BR-8.7. |
| `review` | Внешние ключи на клиента и заказ, `UNIQUE (order_id, entity_type, entity_id)`, `CHECK (rating BETWEEN 1 AND 5)`. | В рамках заказа доступен один отзыв на объект, BR-9.1–9.5. |
| `review` | Текст, дата, тип и ID объекта обязательны. `photo_url` допускает `NULL`. | Состав отзыва, BR-9.3, BR-11.3. |

Пустой агрегированный рейтинг блюда или ресторана означает отсутствие отзывов, BR-9.6–9.7. Связи с адресами используют стандартное поведение внешних ключей без каскадного удаления адресов, BR-3.5. Для статусов и типов используются восемь перечислений PostgreSQL, BR-4.3, BR-5.5, BR-6.2, BR-7.7, BR-7.9, BR-8.2 и BR-9.1.

## Правила, реализованные триггерами

| Правило | Проверка или действие |
| --- | --- |
| BR-7.3 | `check_order_product_restaurant` сверяет ресторан блюда с рестораном заказа. `check_restaurant_change` защищает уже связанные заказы и блюда при смене ресторана. |
| BR-7.14 | Отложенные триггеры проверяют новый заказ и заказ, из которого удалена или перенесена позиция. Проверка в конце транзакции позволяет создать заказ и его позиции отдельными командами. |
| BR-8.7 | `sync_order_pay_status` пересчитывает статус после добавления, изменения и удаления платежей. Успешная попытка даёт `оплачен`, обрабатываемая — `ожидает`, все попытки с ошибкой — `ошибка`. При отсутствии попыток статус `ожидает`. |
| BR-9.2 | `check_review_target` сверяет клиента отзыва с клиентом заказа и проверяет, что объект отзыва относится к заказу. |
| BR-9.6–9.7, FOOD-105 | `rating_change` пересчитывает рейтинг блюда или ресторана при добавлении, изменении и удалении отзыва. У заказа агрегат рейтинга отсутствует. |
| BR-6.6, FOOD-102 | Генератор при положительном размере выборки создаёт как минимум одного работающего курьера. |
